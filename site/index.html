ECHTE DATEN

On-Prem / Cloud verbinden

Zwei Wege, echte Messungen einzuspielen — beide landen als MEASURED-Evidence in experiments/ und aktualisieren die Kennzahlen oben automatisch.

1 · Datei hochladen

Eine result.json (Schema wie von scripts/run_failover.py erzeugt) direkt hochladen.

2 · API anbinden

Für automatisierte Pushes aus eigenem Monitoring/CI, ohne manuellen Upload:

curl -X POST http://localhost:8000/api/ingest \
  -H "Authorization: Bearer <DASHBOARD_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "experiment_id": "PROD-2026-09-03-01",
    "scenario": "primary-failure",
    "rto_seconds": 12.4,
    "acknowledged_write_loss": 0,
    "replication_lag_seconds_max": 0.8,
    "workload": {"p95_ms": 210, "p99_ms": 340, "error_rate": 0.01, "throughput_rps": 48.2}
  }'

Token steht in .env (DASHBOARD_API_TOKEN). Jedes Feld außer experiment_id ist optional.

Was diese Plattform beweisen kann

Nicht: „Hybrid ist immer am besten.“ Sondern: „Unter den dokumentierten Anforderungen und Testbedingungen erfüllt Kandidat X die Gates und zeigt den robustesten Trade-off.“

Grafana beantwortet „Was passierte technisch?“. Diese Seite beantwortet „Was bedeutet das für die Architekturentscheidung?“.
